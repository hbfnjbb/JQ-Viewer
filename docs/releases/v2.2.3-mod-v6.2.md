# JQ Viewer 2.2.3 优化线路版 V6.2

- 发布版本：2.2.3 mod v6.2（最终构建 6.2.5）
- 基于：上游 JQ Viewer 2.2.3（JUKOMU/JQ-Viewer，MIT License）
- 日期：2026-11-25
- 发布仓库：https://github.com/hbfnjbb/JQ-Viewer

## 本版重点

V6.1 之后的一次线路与启动体验重构，Android 与 Windows 桌面端同步更新。

### 图片加载

- 图片改为逐页多线路：解析章节后，每张图片单独从图片运行池取 Host，不再整章共用一条线路。
- 请求前重新选线：缓存里遗留的单 Host URL 会在发起请求前被纠正为当前运行池线路。
- 失败自动换线：单张图片 IO 失败时自动切换下一条线路重试，最多 3 条。
- 自动模式保留全部线路：测速结果只用于排序，运行池保留线路表中的全部图片线路；可用线路排在前面，未测成功的作为后备，不再收敛成单条 Host。
- 测速减负：每条线路只测 1 张图、1 轮，超时 5 秒；测速请求带 `Range: bytes=0-65535`，只取前 64 KB。
- 测速延后：启动后先让首屏图片正常加载，约 6 秒后再在后台测速，避免和首屏抢带宽。

### 线路表与探测

- 线路表本地持久化：核心新增线路表（API 与图片各一张），落盘保存；云端新增线路只做去重追加，不覆盖、不删除本地已有线路。
- 启动只读本地表：启动阶段不再逐条探活，云端域名列表在 ready 后后台增量刷新；图片新线路只入表，不预探活。
- API 探活改为独立短连接：2 秒超时、不重试；初始化失败时在同一次启动内按线路表切换下一条，最多 3 次。
- 启动后复核：ready 后约 20 秒，用 3.5 秒超时在后台复核一轮；手动刷新、手动重探同样使用 3.5 秒。
- 探测并发可设置：设置页“网络状态”新增“图片线路探测并发数”，范围 1–8，默认 4，下次线路探测生效。

### 线路选择与状态

- 手动线路校验：API 探活只把 `HEAD /setting` 返回 2xx 视为可用；手动选择的线路若失败计数显示不可达，自动回退到自动模式并清空旧值。
- 状态稳定：修复 `getDomainStates()` 在“全部探活失败”时对不可变 Map 写值导致的异常；全部超时时保留上一次线路状态，只有首次启动、没有任何历史状态时才显示全红。
- 弹窗不触发重测：打开“选择 API 和图片线路”弹窗只读取上次结果，需要重测时点测速按钮。
- 状态文案：红点仍表示未通过探活，右侧只显示具体毫秒数（如 `3083 ms`）；没有测到数据时显示“不可达”，测速超时显示“超时”。
- 自动优选兜底：自动模式下 `getUsedDomain()` 返回本轮具体可达域名，前端也用可达线路兜底，不再停在“读取中”。

### Windows 桌面端

- 同步实现图片按页多线路、线路表本地持久化、探测并发设置（1–8）、网络状态毫秒显示、自动优选兜底。
- 安装包为用户级安装，默认装到 `%LOCALAPPDATA%\Programs\JQ Viewer`，带桌面/开始菜单快捷方式和卸载项；便携包解压后直接运行 `JQ-Viewer\JQ-Viewer.exe`。
- Linux 仍请使用上游发行包。
